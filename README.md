# NETWORKWALKS-B083-WK4-PM1-PM2-PM3-PM4-PROJECT
Vulnerability Assessment and Penetration Testing


🔐 Mediroza General Hospital — Penetration Testing & Vulnerability Assessment

📌 Project Overview

As part of my cybersecurity training with NetworkWalks Academy, I completed an authorized black-box penetration testing and vulnerability assessment of a healthcare-themed web application, Mediroza General Hospital.

The objective was to identify security vulnerabilities, demonstrate their potential impact within the controlled lab environment, perform reconnaissance, analyze exposed information, and produce a professional penetration-testing report.

«⚠️ Disclaimer: This project was performed in an authorized, controlled educational environment provided by NetworkWalks Academy. No unauthorized systems or real-world targets were tested.»

---

🎯 Project Objectives

The assessment focused on:

- Web application reconnaissance
- Authentication testing
- SQL injection testing
- Access-control assessment
- Patient report security
- PDF encryption analysis
- Metadata analysis
- Sensitive information discovery
- Backup exposure
- Database security
- Vulnerability documentation and reporting

---

🚀 Milestone 1 — Initial Access & Patient Reports

I began by performing reconnaissance against the authorized target and identifying the patient login functionality.

Target

https://medirozahospital.com

I used Burp Suite to intercept and analyze HTTP requests and responses generated by the login functionality.

Initial authentication attempts with invalid credentials did not provide access.

I then tested the application's input handling and identified an SQL injection vulnerability in the login functionality.

The vulnerability allowed authentication controls to be bypassed in the controlled lab environment.

Result

Successful authentication bypass provided access to the patient portal.

The portal contained three laboratory report links:

download.php?id=1
download.php?id=2
download.php?id=3

The reports were downloaded for further security analysis.

---

🔐 Milestone 2 — PDF Encryption Analysis

The downloaded patient reports were encrypted PDF documents.

I first verified their encryption status using:

qpdf --is-encrypted patient_report_1.pdf
qpdf --is-encrypted patient_report_2.pdf
qpdf --is-encrypted patient_report_3.pdf

The reports were confirmed to be encrypted.

Password Recovery

Following the exercise instructions, I tested the supplied wordlist against Report 3.

The initial wordlist failed.

I then switched to the instructor-provided JTR wordlist, which successfully recovered the document password.

I used QPDF to create an unlocked copy for the required analysis:

qpdf --password='[REDACTED]' --decrypt patient_report_3.pdf report3_open.pdf

The password is intentionally redacted from this repository.

Key Lesson

A file being encrypted does not automatically mean it is strongly protected. Password strength and the overall access-control architecture are equally important.

---

🔎 Milestone 3 — Deep Reconnaissance

After unlocking Report 3, I performed metadata analysis using ExifTool:

exiftool report3_open.pdf

The metadata revealed an internal clue indicating that a database backup had been moved to an "/old/" directory.

This became the next stage of the investigation.

---

🤖 robots.txt Analysis

I inspected the site's "robots.txt" file:

curl https://medirozahospital.com/robots.txt

The file contained:

Disallow: /patient/
Disallow: /staff/
Disallow: /old/

The "/old/" entry confirmed the directory identified through the PDF metadata clue.

---

📂 Exposed Backup Directory

I then inspected the "/old/" directory:

curl https://medirozahospital.com/old/

Directory listing was enabled.

The following database backup was exposed:

mediroza_db_backup_2019.sql

I downloaded the backup for analysis within the authorized lab environment.

---

🗄️ Database Analysis

The SQL backup was examined to understand what information had been exposed.

Two important tables were identified:

Staff Table

The staff table contained information such as:

- Staff names
- Job titles
- Departments
- Monthly salaries

Shareholders Table

The shareholders table contained:

- Shareholder names
- Share percentages
- Share classes

The metadata clue "j.malik" was also correlated with the staff record for Jameel Malik, identified as an IT Systems Administrator.

This connected the investigation from:

PDF Metadata
     ↓
j.malik
     ↓
Jameel Malik
     ↓
IT Systems Administrator
     ↓
/old/
     ↓
Database Backup

This demonstrated how seemingly minor information disclosure can assist deeper reconnaissance.
